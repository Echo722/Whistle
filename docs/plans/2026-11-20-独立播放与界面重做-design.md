# 独立播放与界面重做：设计方案

日期：2026-11-20
状态：P1–P6 主链路已落地主线（2026-11-23），待真人桌面体验验收（§7 个别键位微调留待体验反馈）
取代：`音效语义搜索系统_方案与开发阶段规划_v1.md` 第 8.4 节（REAPER 播放）与 1.2 节「第一版试听先使用 REAPER」

---

## 1. 意图与缘由

当前桌面工具能搜，但不能"听"。试听要走 `POST /v1/playback/start` → 服务 → REAPER 桥 → REAPER 播放，因此：

- 空格键按不动——整条本地试听链路不存在，不是漏绑快捷键；
- 播放头是「桥观测位置 + 单调时钟线性推进」的**界面推算值**，不是声卡回读；
- 每次试听要等一次网络往返，且依赖 REAPER 开着、桥活着、工程状态正常；
- 界面为此堆了一整套回执状态机（待执行／已核查现场／结果不确定）占据主界面。

使用者的实际工作循环是：选中第一个 → 点波形从该处播放 → 空格暂停 → 方向键切下一个并从头发声 → 看中双击插入。这是 Media Explorer 的肌肉记忆，一小时发生几百次。

**试听是最高频的动作，却挂在最低频的外部条件上。** 本方案把试听改为本机声卡直出，REAPER 只承担"落地"这一低频动作，并把落地设计成不依赖任何特定 DAW 的形态。

---

## 2. 目标、非目标、反目标

### 目标

1. 试听不依赖 REAPER：REAPER 未启动、未连接、工程异常时，空格与方向键照常工作。
2. 播放头可信：播放位置来自声卡回调的实际帧计数，不是推算。
3. 复刻 Media Explorer 的键盘手感（详见第 7 节）。
4. 继承 MediaEye 的封面链，让封面进入切行节奏而不是当装饰。
5. 落地与 DAW 解耦：拖出是通用路径，特定 DAW 适配器只是加速器。
6. 界面从「验收报告」改为「乐器」。

### 非目标

- 不做音频编辑、不变速变调、不加 VST、不做波形精细修剪。
- 不做云端库、素材商店、团队协作。
- 不改检索能力（索引、向量、融合排序保持现状）。
- 首版不做多声道环绕试听（立体声与单声道即可）。

### 反目标（技术上成立也算失败）

- 试听仍然需要先打开 REAPER。
- 空格键在搜索结果表里失效，或光标在搜索框时空格无法输入空格。
- 为了让封面出图而把整库文件逐个扫描、拖慢首次搜索。
- 为了"顺手"把插入改成静默直发、失败后界面无任何反馈。
- 删除旧桥后留下半死不活的死代码与无人认领的测试。

| 项 | 约束 |

## 4. 架构决策

### 4.1 核心取舍：播放本地化，落地适配器化

```
搜索/索引        Python 服务（不变）
试听             本机声卡（新增，不经过 HTTP）
落地             拖出（通用） ／ DAW 适配器（加速）
```

**拖出是通用路径，适配器是加速器。** 这是"以后换 DAW 也能用"的答案：任何 DAW 都接受 Windows 文件拖放，所以即使没有任何适配器，工具依然可用。REAPER 适配器只是把「双击插入到指示器位置」这类快捷动作做快。

### 4.3 新增数据通道（三个端点）

| 端点 | 用途 | 备注 |
|---|---|---|
| `GET /v1/assets/{id}/audio` | 播放源。支持 `Range` 请求 | 流式；按稳定 ID 取，服务端解析绝对路径 |
| `GET /v1/assets/{id}/cover` | 封面原图字节 | 直接吐 jpg/png/bmp，服务端不解码不缩放 |
| `POST /v1/assets/{id}/materialize` | 返回一个**可拖拽的本机路径** | 无选区时返回源文件绝对路径；带 `source_range` 时先渲染临时 wav 再返回其路径 |

`/materialize` 是拖放能力的关键：Windows 的 `CF_HDROP` 只接受磁盘上的真实文件，而桌面进程至今拿不到任何绝对路径（`AssetLocation` 只有 `relative_path`，且校验禁止盘符与 `..`）。绝对路径只在服务侧由 `catalog_view.path_for()` 解析。该端点只在本机回环下可用，与现有鉴权一致。

三者都遵循现有错误语义。`/audio` 与 `/cover` 为幂等读；`/materialize` 在带选区时会在 `.local/` 下产生临时文件，需要明确的清理策略（按最近 N 次或按启动清理）。

### 4.4 播放引擎选型

**推荐 `sounddevice` + `soundfile`。**

理由：空格续播、点哪播哪、上下键秒切，三条都要求 seek 在 10 ms 级且播放位置可读；`sounddevice` 的回调流给出每块实际帧数，播放头是该计数的直接换算，**不存在推算**。`soundfile` 用 libsndfile 解码，覆盖 wav/aif/flac/mp3/ogg，补上现有 `audioio/decode.py` 只认 WAV 的缺口。

备选 `miniaudio`（单包，解码+播放一体）。若 `soundfile` 在某格式上失败，可退到它。

**不选 `QMediaPlayer`**：位置回报百毫秒粒度，无法支撑点击波形的精度，也无法消掉「播放头是估计值」这条现存缺陷。且需装 `PySide6-Addons`（比 `Essentials` 大）。

播放器实现要点：

- 一个线程持有 `sd.OutputStream`，回调里从预解码的 float32 缓冲区取块；
- 缓冲区按需分块解码，不整文件载入（参照 `audioio/decode.py` 的流式风格）；
- 切行时直接换源并重置帧计数，不做淡出——Media Explorer 也是硬切；
- 设备不可用（无声卡、独占被占）要成为明确状态，不是静默无声。

**采样率策略（此处修正过一次）：** `audioio/resample.py` 是**整段式** API——`resample(samples, src_rate, dst_rate)` 的连续性只在单次调用内成立，逐块调用会在每个块边界产生接缝。素材库以 96k/24 为主，设备多为 48k，这个接缝是必然遇到的。因此：

1. 优先让 `OutputStream` **直接以文件采样率打开**（多数接口支持 44.1 / 48 / 88.2 / 96）；能开就不重采样，零接缝、零额外内存。
2. 设备不支持该采样率时，**整文件重采样**后播放，长度上限 120 秒（96k 立体声约 92 MB）。素材库 43% 短于 2 秒，绝大多数落在这条路。
3. 超长文件（BGM 级）：按块解码、以设备率直出，接受轻微音高偏移，界面明确标注「已变速播放」。
4. 带滤波器状态的流式重采样器留到确有需要时再做，不在 P1。

## 5. 封面链路（继承 MediaEye）

来源：MediaEye（`MediaEye.lua`）

### 5.1 优先级（照搬 `MediaEye.lua:998-1020`）

1. **命名为封面的文件夹图片** — 文件名主干命中 `folder / cover / front / album / artwork / art / jacket / poster`
2. **文件内嵌图** — MP3 ID3v2 `APIC/PIC`、WAV 的 `id3 ` chunk、FLAC `PICTURE` 块
3. **附近任意图片** — 兜底

### 5.2 目录扫描评分（照搬 `find_folder_image`）

- 扫描顺序：同目录 → 同目录子目录（素材型子目录 0.9，其它 0.7）
- 向上三层父目录，衰减权重 `0.60 / 0.40 / 0.25`
- 每层父目录**只扫素材型子目录**（`artwork / art / documents / document / docs / doc / images / pictures / pics / covers / scans`），权重 `0.85 / 0.70 / 0.55`。注意单数形式 `document`、`doc` 也在表里，漏掉会误判。
- 名称评分：主干预设关键词 = 4，包含关键词 = 3，等于音频文件名 = 2，其它 = 1

这条限制必须保留：不限制会预览 PackA 音效时抓到同父目录下 PackB 的封面。

### 5.3 与现有代码的两处落差

- `catalog/embedded.py` 的 `FAMILIES` 只有 `bext / info / ixml`，**不认 `id3 ` chunk 与 FLAC PICTURE**。内嵌图解析要新写（约 250 行），不能复用。
- MediaEye 是纯 Lua 手写解析、依赖 `js_ReaScriptAPI`；我们改用 Python 重写，无该依赖。

### 5.4 按需计算 + 目录级缓存

**不在导入期计算。** 理由：`catalog` 是 0.1.0 公共契约，加封面字段要动 schema 版本语义；目录结构变化后按需能自适应。

缓存键取**目录**而非文件——同包几百个音效共享一张封面，滚动时只扫一次。MediaEye 逐文件扫是因为它一次只看一个；我们一屏 20 行不能这么干。

## 6. 视觉系统

### 6.1 设计前提

使用场景的物理条件是暗房间、双屏、长时间注视。这不是审美偏好而是约束：浅底大面积白会刺眼。同时要避免把「深色底 + 单一亮色」当作默认答案——那正是生成式界面的常见套路。

本工具的身份来自它解决的问题：**用意思找声音**。视觉上唯一有生命的元素应该是波形与播放头，其余全部安静。

### 6.2 色板

深冷灰阶，非纯黑；两个信号色分管两件不同的事。

| 令牌 | 值 | 用途 |
|---|---|---|
| `bg-canvas` | `#12151A` | 最深：波形井、表格空白区 |
| `bg-panel` | `#1A1E25` | 面板表面 |
| `bg-raised` | `#222831` | 悬停行、工具条 |
| `line` | `#2C333E` | 发丝线、网格、分隔 |
| `text` | `#CDD3DC` | 主文本 |
| `text-dim` | `#79838F` | 次要列、说明 |
| `text-faint` | `#525B66` | 三级、禁用 |
| `signal-select` | `#1F3350` | 当前行填充 |
| `signal-select-mark` | `#5B93D6` | 当前行左侧 2px 标记 |
| `signal-play` | `#EE9B2E` | 播放头、已播波形填充、行内进度 |
| `state-offline` | `#5A636E` | 离线素材整体降饱和度 |

**为什么是两个信号色而不是一个：** 选中是**结构状态**（哪一行是当前），播放是**时间状态**（声音正在发生）。合并成一个颜色会让「选中的静止行」和「正在响的行」无法区分，而这恰是试听时的核心判断。暖色留给播放也符合 DAW 惯例（REAPER 播放光标即暖色），不是装饰性选择。

离线素材走灰而不是黄：它不危险，只是不可用。

### 6.3 字体

- UI：`Segoe UI`，中文回落 `Microsoft YaHei UI`
- 数字：`Cascadia Mono`，回落 `Consolas`

数字字体**只用于需要列对齐的位置**——时长、采样率、声道、时间标尺、进度数值。这不是「用小号等宽体装饰标签」，而是让 24.5s / 1.8s / 103.2s 在列里右对齐时小数点成列。

字号（px，96 dpi）：

| 用途 | 字号 |
|---|---|
| 标尺刻度、行内辅助 | 11 |
| 次要列、状态栏 | 12 |
| 行主文本、输入框 | 14 |
| 检查器标题（素材名） | 15 |

- **左：结果列表**，占满剩余宽度，行高 28px。虚拟滚动，行内不建控件。

### 6.5 视觉原则

- **只在播放上用力。** 播放时：波形已播部分填 `signal-play`，当前行底部一条 2px 同色进度线。其余一切静止、无动画、无阴影。
- **平面分隔。** 面板之间只有发丝线，无圆角卡片、无投影、无渐变。
- **表格是表格。** 不做成卡片列表；行高固定，列宽可拖，双击分隔线复位。
- **封面不抢戏。** 检查器里是唯一的大图；列表行内默认不放缩略图（见 10.1）。
- **留白克制。** 行内水平 padding 8px，垂直不留空；面板内边距 12px。

## 7. 键盘与鼠标规格

### 7.1 全局键位

| 键 | 行为 |
|---|---|
| `Space` | 播放／暂停。暂停保留位置，继续时从该处播放 |
| `↑` / `↓` | 切上一行／下一行；**切换后从 0 自动播放** |
| `Enter` | 插入当前素材到 DAW 指示器位置 |
| `Esc` | 先清除选区；无选区时停止播放 |
| `←` / `→` | 播放头微移 10 ms；`Shift` 加按为 100 ms |
| `Ctrl+F` | 聚焦搜索框 |
| `F5` | 重试上次失败的搜索（保持现状） |

### 7.2 波形区

| 操作 | 行为 |
|---|---|
| 单击 | 从该点开始播放 |
| 拖拽 | 建立选区（`[start, end)`），不自动播放 |
| 拖拽选区出窗口 | 渲染选区为临时 wav 并拖出 |
| 滚轮 | 横向缩放；`Ctrl+滚轮` 平移 |
| 双击 | 缩小视图到全文件 |

### 7.3 列表区

| 操作 | 行为 |
|---|---|
| 单击 | 选中，不自动播放 |
| 双击 | 插入到 DAW 指示器位置 |
| 拖拽出行 | 拖出原文件 |
| 右键 | 菜单：插入到新轨道／在新轨道打开／复制路径／记录问题 |

### 7.4 焦点规则（易错点）

- 焦点在搜索框内时，`Space` 必须输入空格，**不得触发播放**。
- 焦点在列表或波形区时，`Space` 触发播放。
- 焦点区域用 2px `signal-select-mark` 边框标示，让使用者知道当前按键会作用在哪。
- 输入法组字期间不拦截任何按键。

### 7.5 插入目标

- 有选中轨道 → 落在该轨道、指示器位置。
- 无选中轨道 → **新建一条轨道**，落在指示器位置（与 Media Explorer 一致）。
- 指示器位置由 DAW 适配器读取；读不到时按钮与 `Enter` 禁用并说明原因，不回退到猜测位置。

## 8. 落地与 DAW 解耦

### 8.1 三条落地路径

| 路径 | 依赖 | 说明 |
|---|---|---|
| 拖原文件出行 | 无 | `POST /materialize` 拿绝对路径，走 Windows `CF_HDROP`，任何 DAW 都接 |
| 拖选区出行 | 无 | `POST /materialize` 带 `source_range`，服务端渲染临时 wav 后拖该文件 |
| 双击／`Enter` 插入 | DAW 适配器 | 最快，但可选 |

前两条不依赖任何适配器。这是"换 DAW 也能用"的保证。

### 8.2 REAPER 适配器需要改 Lua——不是现成能力

**修正：** 前稿写「现有 Lua 桥的能力远超这两件」，对插入成立，对**读取不成立**。核对结果：

- `reaper/audiosearch_bridge.lua`（715 行）里没有任何 `GetCursorPosition` / `GetSelectedTrack` / `CountSelectedTracks`；
- `write_status()` 发布的 status 只有工程与轨道列表（id / name），**没有光标位置，也没有当前选中轨**；
- 因此 §7.5 的指示器位置和 §9.2 的两个新字段，**都必须改 Lua 侧**——每次 heartbeat 附带光标与选中轨。这份 Lua 改动（以及 `tests/playback/lua/` 的 mock、`test_reaper_lua.py`）必须在 P5 的任务清单里明确列出。

**「无选中轨道时新建轨道」目前协议不支持。** `InsertRequest.target.track_id` 是必填 `NonEmpty`，`check_target()`（`playback/validation.py:141`）要求轨道在该工程中已存在，Lua 的 `cmd_insert` 找不到轨道会直接 `reject(target_changed)`；`test.add_track` 只在 `TEST_COMMANDS=1` 下可用。三条路径取一：

1. **改 Lua 加正式命令**：把 `add_track` 提升为正式命令，插入前先建轨再插入。推荐。
2. 两段式：客户端先 `add_track`、再 `insert`，两次往返。
3. 首版退化：无选中轨时禁用插入并说明原因（不符合 Media Explorer 行为，不推荐）。

推荐 1。它在协议上是 additive 的一条命令，比两段式少一次往返，也不改变现有 `InsertRequest` 语义。

插入结果处理：`completed` → 行内闪一下位置信息；`rejected` → 状态栏红字；`uncertain` → **必须**在行内显式标出并要求用户核查，不允许静默。这条是安全底线，不能因为界面变轻而丢。

### 8.3 未来 DAW

适配器接口按「读光标／读选中轨／插入」三方法定义。新增 DAW 只实现这三件，不需要碰播放。

### 9.1 新增（additive，0.1.x）

### 9.2 收缩

`PlaybackStartRequest` / `PlaybackStopRequest` / `PlaybackSeekRequest` 不再服务于试听。是否物理删除，取决于是否保留「在 REAPER 里试听」作为可选模式。

**建议：保留端点，桌面不再调用。** 理由：删除会让 `contracts/models.py` 的版本语义变动，而版本还是 0.1.0；保留端点不影响本地播放。另有一个硬约束——`integrations/reaper/bridge.py` 直接 import 这五个 playback 模块，端点在、模块就在，删除不是删一个文件的事。

`CommandReceipt` 是**四态**：`accepted` 是过渡态，`completed / rejected / uncertain` 是终态。前稿写「三态」指终态，实施时按四态处理。

`/v1/reaper/status` 需新增 `edit_cursor_seconds` 与 `selected_track_id`（可为 null）以支撑插入。该文件设计上允许 additive 增量，但**前提是 Lua 侧先能读出来**（见 8.2）。

## 10. 已定的取舍

### 10.1 列表不放封面缩略图（已定）

**决定：列表保持 28px 行高，不放行内缩略图。** 封面只出现在右侧检查器——选中哪条素材，那里显示它的封面大图。

理由：一屏 25 行比 14 行重要。挑素材主要靠名字和包名扫读，封面解决的是「这个包是什么」，不是「这一条是什么」。

因此不做网格视图，也不做视图切换。检查器 300px 宽，封面 240px 方图。

### 10.2 拖选区的默认处理

选区拖出时，渲染的 wav 是否加淡入淡出？加则不会有爆音，但会改变素材原貌；不加则可能拖进 DAW 时有咔哒声。建议**默认不加**，提供 `Alt` 拖拽加 5ms 淡变。

### 10.3 收藏／标签不进首版（已定）

现在没有收藏功能。试听体验做好后，最自然的下一步是标记，但它涉及新的写入库与界面位置。建议**不进首版**，先把手感立住。

### 10.4 起点提交：`e06123f`（已定）

similar 那批改动已收口为 `e06123f`「feat: 以参考素材找相似，并让整库能进得来」（15 个文件、+637 行），工作树干净，`tests/test_similar_api.py` 与 `tests/desktop` 在该提交上全绿。

**本方案从 `e06123f` 起步。** 它已包含 `main_window.py` 的最新形态，P2 重写时不会再和未提交的改动打架。

### 10.5 桌面依赖分组：numpy 移入独立 `playback` 组（已定）

`sounddevice` + `soundfile` 需要 numpy，而 numpy 现在只挂在 `ai` 组（和 torch / transformers 绑在一起）。桌面进程要跑重采样就必须拿得到 numpy，但不该顺带拖进 torch。

**决定：新建 `playback` 依赖组，含 `numpy`、`sounddevice`、`soundfile`；桌面安装时加 `--group playback`。** `pyproject.toml` 与 `uv.lock` 按项目规则由 Lead 执行。

打包影响：PyInstaller 产物会新增 PortAudio 与 libsndfile 两个原生 DLL，发布体积需重新记录。
